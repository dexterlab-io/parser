# DexterLab Glossary

(Version 2026 — Unified Command Ecosystem Terminology)

This glossary defines the principal terms used throughout the DexterLab command ecosystem.

It covers:

- Parser terminology
- Command interfaces
- Backend architecture
- Arbitration concepts
- Memory regions
- Error handling
- Verification infrastructure
- Hardware master integration

The glossary serves as the common vocabulary for all DexterLab documentation.

---

# 1. Command Interfaces

## t_cmd_out

Protocol-independent command structure generated by:

- Parser Engine
- Hardware Master

Contains:

```text
cmd_write
cmd_burst
cmd_wrap
cmd_fifo

cmd_id
cmd_addr
cmd_len

cmd_data
cmd_wstrb

cmd_prot
cmd_size
cmd_lock
cmd_cache
cmd_qos

cmd_err_code
```

Used by all supported backends.

---

## t_rsp_out

Response flow-control interface.

Contains:

```text
rsp_ready
rsp_err_ready
```

Used by command sources to indicate response acceptance.

---

## t_rsp_in

Protocol-independent response interface produced by backends.

Contains:

```text
rsp_valid
rsp_last
rsp_data
rsp_id

rsp_err_valid
rsp_err_code
rsp_err_addr
rsp_err_beat
rsp_err_id

rsp_end_cmd
```

Used to return execution results and command-completion status.

## Burst Commands

```text
BURST_READ

```

---

## Wrap Commands

```text
WRAP_READ

WRAP_CHECK
```

Multi-beat wrapping operations.

---

## FIFO Commands

```text
FIFO_READ
```

Operations targeting FIFO endpoints.

---


# 3. Command Attributes

## cmd_write

```text
1 = WRITE
0 = READ
```

---

## cmd_burst

Indicates an incrementing burst transaction.

---

## cmd_wrap

Indicates a wrap transaction.

---

## cmd_fifo

Indicates FIFO-oriented execution.

---

## cmd_lock

Requests ownership retention by the arbiter.

Generated by:

```text
SET_ATOMIC
```

---

## cmd_len

Number of beats associated with a transfer.

---

## cmd_wstrb

Byte-enable mask used for partial writes.

---

## cmd_id

Unique command identifier.

Used for response correlation.

# 4. Memory Regions

## REG Region

```text
0x0000 – 0x001F
```

Contains:

```text
REG0
REG1
REG2
REG3
REG4
REG5
REG6
REG7
```

Supports single-beat operations.

---

## RAM Region

```text
0x1000 – 0x2FFF
```

Supports:

- Burst transfers
- Wrap transfers
- WSTRB operations
- Polling
- Dumping
- Fill operations

---

## FIFO Region

```text
FIFO_WRITE -> 0x3000

FIFO_READ  -> 0x3100
```

Supports streaming push/pop operations.

---

# 5. Burst and Wrap Concepts

## Incrementing Burst

Address increases sequentially.

Example:

```text
addr + beat_offset
```

---

## Wrap Transaction

Transaction that wraps within a defined address boundary.

The parser validates:

- Wrap size
- Alignment
- Command legality

The backend generates the actual wrap addresses.

---

## 4KB Boundary Rule

Large operations may not cross a 4KB boundary.

The parser may split large logical operations into multiple executable micro-commands.

---

# 6. FIFO Concepts

## FIFO_WRITE

Pushes data into a FIFO structure.

---

## FIFO_READ

Removes data from a FIFO structure.

---

## FIFO_CHECK

Verifies FIFO contents against expected values.

---

## FIFO Underflow

Attempt to read from an empty FIFO.

---

## FIFO Overflow

Attempt to push data into a full FIFO.

# 7. Error Handling

## Unified Error Model

DexterLab groups runtime errors into backend-specific ranges:

```text
AXI_FULL  : 0–15
AXI_LITE  : 16–31

AHB_FULL  : 32–47
AHB_LITE  : 48–63
```
