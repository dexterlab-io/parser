# DexterLab Parser Error Specification
This document defines all error conditions that may occur during command parsing,
semantic validation, and execution.  
Errors are divided into three categories:

1. Syntax errors (file parsing)
2. Semantic errors (command validation)
3. Runtime errors (backend execution)

Each error type is mapped to a hardware error code (`rsp_err_code`) when
possible.

---

# 1. Syntax Errors (Parsing Stage)

Syntax errors occur while reading the `.cmd` file.  
They prevent command generation and stop the parser immediately.

## 1.1 Unknown Command
The parser encountered a keyword that is not recognized.

Example:
WRITEE 0x1000 0x55

Codice

## 1.2 Missing Arguments
A command does not contain the required number of fields.

Example:
WRITE 0x1000

Codice

## 1.3 Invalid Number Format
Address or data fields are malformed.

Examples:
WRITE 0xZZZZ 0x55
READ 12AB34G

Codice

## 1.4 Invalid Burst Length
Burst length is zero or negative.

Example:
BURST_READ 0x1000 0

Codice

## 1.5 Invalid Wrap Length
Wrap length is not a power of two.

Example:
WRAP_READ 0x2000 6

Codice

## 1.6 Data Count Mismatch
Number of data words does not match burst length.

Example:
BURST_WRITE 0x1000 4  0xAA 0xBB

Codice

---

# 2. Semantic Errors (Validation Stage)

Semantic errors occur after parsing, when the command is validated.

## 2.1 Address Misalignment
Address is not aligned to bus width.

Example:
WRITE 0x1003 0x55

Codice

## 2.2 Burst Crossing Forbidden Boundary
AXI: burst crosses 4KB boundary  
AHB: burst crosses region boundary (implementation-specific)

Example:
BURST_READ 0x0FFF 4

Codice

## 2.3 Wrap Mask Error
Wrap burst length does not match wrap mask.

Example:
WRAP_WRITE 0x2000 8  <data...>

Codice
(where backend supports only 4-beat wraps)

## 2.4 FIFO Mode Misuse
FIFO commands used on non-FIFO addresses.

Example:
FIFO_READ 0x80000000 4

Codice

## 2.5 Atomic Mode Misuse
Atomic block contains unsupported commands.

Example:
ATOMIC_BEGIN
BURST_READ 0x1000 16
ATOMIC_END

Codice

---

# 3. Runtime Errors (Backend Stage)

Runtime errors occur during execution on AXI/AHB.

These errors are reported through `rsp_err_valid = 1`.

## 3.1 SLVERR (0x01)
Slave error.

Causes:
- invalid register access
- peripheral error
- unsupported operation

## 3.2 DECERR (0x02)
Decode error.

Causes:
- unmapped address
- access to non-existent region

## 3.3 BOUNDARY_ERR (0x03)
Burst crosses forbidden boundary.

Generated by backend.

## 3.4 BURST_ERR (0x04)
Backend cannot execute burst.

Causes:
- unsupported burst type
- unsupported wrap length

## 3.5 CHECK_ERR (0x05)
CHECK command mismatch.

Example:
CHECK 0x1000 0x55

Codice
but read value is `0xAA`.

## 3.6 FIFO_ERR (0x06)
FIFO underflow or overflow.

Example:
- reading from empty FIFO  
- writing beyond FIFO capacity

# 4. Error Mapping Table

| Error Type | Parser Stage | Hardware Code | Description |
|------------|--------------|---------------|-------------|
| Unknown command | Syntax | — | stops parser |
| Missing arguments | Syntax | — | stops parser |
| Invalid number | Syntax | — | stops parser |
| Burst length invalid | Syntax | — | stops parser |
| Wrap length invalid | Syntax | — | stops parser |
| Data mismatch | Syntax | — | stops parser |
| Misalignment | Semantic | DECERR | backend rejects |
| Boundary crossing | Semantic | BOUNDARY_ERR | backend rejects |
| Wrap mask error | Semantic | BURST_ERR | backend rejects |
| FIFO misuse | Semantic | SLVERR | backend rejects |
| Atomic misuse | Semantic | SLVERR | backend rejects |
| Slave error | Runtime | SLVERR | backend error |
| Decode error | Runtime | DECERR | backend error |
| Burst error | Runtime | BURST_ERR | backend error |
| Check mismatch | Runtime | CHECK_ERR | backend error |
| FIFO error | Runtime | FIFO_ERR | backend error |

---

# 5. Error Propagation

Errors propagate as follows:

backend → wrapper → arbiter → parser → user

Codice

The parser receives:

rsp_err_valid = 1
rsp_err_code  = <code>
rsp_err_info  = <address>

Codice

The parser logs the error and stops execution unless configured otherwise.

---

# 6. Summary

DexterLab defines three classes of errors:

- **Syntax errors**: stop parsing immediately  
- **Semantic errors**: prevent command execution  
- **Runtime errors**: reported by backend during execution  

All errors are mapped to a unified hardware error code system.

This document defines the complete error model used by the DexterLab parser and
backend.
